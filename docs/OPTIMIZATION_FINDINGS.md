# 优化发现

本文件记录优化过程中发现、但不一定在当前阶段立即修复的问题。每项均保留证据、影响和是否阻塞当前阶段。

## P0-REL-01：版本字段漂移

- 现象：`package.json`、Cargo manifest 与 Tauri 配置均为 `0.8.1`，但 `package-lock.json` 根包仍为 `0.7.4`。
- 证据：阶段 0 中运行 `npm install` 会将 lockfile 根包版本改为 `0.8.1`。
- 影响：发布版本判断、可复现依赖安装和后续 updater 元数据存在歧义。
- 建议优先级：P0（发布可靠性）。
- 是否阻塞当前阶段：否；阶段 1 的原生错误传播不依赖版本号。应在发布自动化阶段使用受控的版本同步脚本一次性修复。

## P0-REL-02：更新清单签名与发布版本疑似不匹配

- 现象：`latest.json` 的版本与 URL 为 `0.8.1`，但其 base64 签名备注文本包含 `OrbitStart_0.6.0_x64-setup.exe`。
- 证据：`latest.json` 当前 `windows-x86_64.signature` 解码后的可信备注。
- 影响：客户端更新验签可能失败；更严重时，人工复制旧签名会掩盖错误的升级产物。
- 建议优先级：P0（发布与数据可靠性）。
- 是否阻塞当前阶段：否；但阻塞任何新的 updater 发布。必须用实际 `0.8.1` 安装包、对应私钥和从上一版本升级的测试路径验证后，才能生成替换清单。

## P0-DB-01：全屏检测轮询反复执行数据库初始化

- 现象：`open_db()` 目前约有 72 个实际调用点，并在每次调用时运行 `init_db()`；悬浮球全屏检测线程约每 500 ms 调用一次。
- 证据：`src-tauri/src/main.rs` 的 `open_db`、`init_db` 与全屏 worker（约第 7397 行）调用链。初始化还包含 schema 检查、默认数据写入和插件模板写入。
- 影响：悬浮球开启后可能持续造成 SQLite I/O、锁竞争、CPU 占用和不必要文件写入。
- 建议优先级：P0（后台占用和数据可靠性）。
- 是否阻塞当前阶段：否；按执行顺序在原生调用错误修复后处理。

## P1-TEST-01：主题 E2E 在当前执行环境未得到最终结果

- 现象：`npm run test:e2e` 以延长预算重跑后 12/12 通过；但 `npm run test:e2e:themes`（23 个用例）在 15 分钟诊断预算内未输出 Playwright 的最终汇总。
- 证据：阶段 0 命令超时记录；基础套件通过记录为 3.9 分钟。
- 影响：当前不能把基础 E2E 标记为通过，也不能据此判断产品回归。
- 建议优先级：P1（验证可靠性）。
- 是否阻塞当前阶段：否；后续应定位具体主题用例或测试环境等待点，而不能删除测试或把超时视为通过。

## P1-NATIVE-01：悬浮球后台初始化错误仅记录到日志

- 现象：阶段 1 后，悬浮球的 `loadSnapshot()` 错误会作为 `NativeCommandError` 被记录，但 `useBubbleWindowSettings` 与主题加载 effect 仍使用 `console.error`，没有可见的窗口级错误状态。
- 证据：`src/App.tsx` 的悬浮球 settings/theme 加载 effect。
- 影响：用户可能只看到悬浮球未按预期加载，无法直接得知 IPC 失败原因。
- 建议优先级：P1（错误可观测性）。
- 是否阻塞当前阶段：否；不会导致数据降级或伪造成功，后续应在不改变悬浮球交互的前提下增加轻量错误提示。
